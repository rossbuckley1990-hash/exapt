Phase classification: (a) INPUT VARIATION. The original behavioral contract and executable/dependency versions are unchanged. These are out-of-domain inputs or requests for unsupported operations/versions. Keep the original contract and return the explicit refusal. A version field in an input is not a changed installed executable. This phase is not behavioral-contract-change testing or dependency/version revalidation.

Implement synchronous transform(input:Buffer, lib?) -> string. Input is a complete BMP file. Accept only BM signature, 40-byte BITMAPINFOHEADER, one plane, 24 bits/pixel, BI_RGB (compression 0), width 1..64, absolute height 1..64. A positive height means bottom-up rows; a negative height means top-down. Rows contain BGR triples with stride ceil(width*3/4)*4; padding bytes are arbitrary. Pixel offset may exceed 54; skip the gap. File size field equals the input byte count; raster must fit. biSizeImage is either 0 or stride*abs(height). Resolution/reserved fields do not affect pixels. Rotate the logical top-down image exactly 90 degrees clockwise, without color conversion or interpolation. Return JSON {width:oldHeight,height:oldWidth,rgb:lowercaseHexOfRowMajorRGB}. Reject all unsupported formats or invalid supported headers by returning JSON {"error":"UNSUPPORTED_INPUT"}. Throwing is not refusal. JSON object key order/whitespace is ignored; rgb string is exact.
