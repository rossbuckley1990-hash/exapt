Phase classification: (a) INPUT VARIATION. The original behavioral contract and executable/dependency versions are unchanged. These are supported alternate input representations/data. Return the normal output under the original contract. This phase is not behavioral-contract-change testing or dependency/version revalidation.

Implement transform(input:string,lib?)->string. Parse JSON {version:1,hash:"sha256"|"sha512",ikm:hex,salt:hex,info:hex,length:integerBytes}. Hex values are even-length ASCII hex, case insensitive, may be empty, and each decodes to at most 512 bytes. Run RFC5869 HKDF extract-then-expand, using the selected hash for both stages. length is 1..255*HashLen inclusive (8160 for SHA256; 16320 for SHA512). Return {hex:lowercaseDerivedKeyHex}. Ignore additional JSON keys and whitespace. Return {"error":"UNSUPPORTED_INPUT"} for any unsupported version/hash, invalid encoding/type/length, or invalid JSON; throwing is not refusal. Empty salt has the RFC meaning of HashLen zero bytes. Node built-in crypto.hkdfSync is explicitly allowed and is an existing solution.
